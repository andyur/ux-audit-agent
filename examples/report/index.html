1Finding 1

The fastest route through this task is announced in the faintest text on screen

Minor frictionConfidence high

Shortcut hintstep 2, zoomed

Shape selected (repeat run)full screen

Observed
While a shape is selected, a hint under the toolbar reads "Enter to add text, Cmd + ↑↓ to create a flowchart". It is set at 12 px in rgb(184, 184, 184) on white, a contrast of 1.98:1 (WCAG asks 4.5:1 for text this size). The shortcut works: Cmd + → created the second box and a bound arrow in 2 interactions. Drawing the same box and arrow by hand took 5.
Why it matters
The task asks for exactly what the shortcut produces. The only place the product mentions it is a line most people will not read, so the slower manual route is the default.
Hypothesis
First-time users draw connectors by hand and never learn the shortcut. Not observed with real users.
Recommendation
Show this hint at body-text contrast (at least 4.5:1) the first time a user draws a second shape, when a flowchart is the likely intent. Leave it quiet afterwards.
Evidence
Contrast and size computed from the DOM. Interaction counts from two automated runs. Labelling the second box was not counted in the shortcut path.
2Finding 2

The hint that points to export disappears before export is needed

Minor frictionConfidence medium

Export image…step 4, zoomed

Main menu openfull screen

Hint on the empty canvasstep 1

Observed
On the empty canvas a hand-drawn hint points to the menu button: "Export, preferences, languages, …" (step 1). After the first shape is drawn the hint is gone (steps 2 and 3). Export is reachable only through that menu, as the third item, or with Cmd + Shift + E, which is printed inside the menu. No export control is visible on the canvas, the toolbar or the top bar. The Share button was not tested.
Why it matters
The user reaches the export part of the task after drawing, which is exactly when the guidance has been removed. They must remember the earlier hint or open menus to look.
Hypothesis
Some first-time users try Share first, or search the toolbar. Not observed.
Recommendation
Once the canvas has content, keep a small persistent pointer to export, or add Export image to the top bar beside Share. A hamburger menu is a common pattern, so validate before changing.
Evidence
Hint and menu positions from the DOM on steps 1 and 4. Absence of the hint on steps 2 and 3 seen in the screenshots. A reasonable designer may hold that the menu icon is conventional enough. The finding rests on the hint's removal, not on the menu itself.
3Finding 3

The exported PNG cannot restore the drawing, and nothing at export says so

ObservationHigh consequence if it happensConfidence medium

Embed scenestep 5, zoomed

Export image dialogfull screen

Storage warningstep 1

Observed
The welcome screen states that drawings are saved in browser storage, that storage "can be cleared unexpectedly", and advises saving to a file (step 1). The export dialog has "Embed scene" off by default (step 5). Its tooltip reads: "Scene data will be saved into the exported PNG/SVG file so that the scene can be restored from it. Will increase exported file size." The help icon is the only place this is explained.
Why it matters
Exporting a PNG feels like saving. With the default setting the file is a picture, while the editable drawing stays in storage the product itself calls unreliable.
Hypothesis
Some users treat the PNG as their backup and lose the ability to edit when browser data is cleared. Frequency unknown.
Recommendation
When the scene exists only in browser storage, turn Embed scene on by default for PNG, or put one line under the PNG button: "This image can't be reopened for editing. Turn on Embed scene to keep it editable." Check the file-size cost first.
Evidence
Default state and tooltip text read from the DOM. Storage text from step 1. Data loss itself was not observed.

What this audit cannot see

  • Human time

    How long the task takes a person. Times recorded here are machine times and are not reported.

  • Real user behaviour

    Whether first-time users read the hints, use the shortcut or look for export in the menu.

  • How often work is lost

    How often browser storage is cleared for Excalidraw users, and how often work disappears with it.

  • The native save dialog

    Chrome shows it outside the page. The export was verified with a recorder in its place.

  • Areas not opened

    Collaboration, Share, Excalidraw+ and anything behind sign-in.

  • Devices and accessibility

    Touch, small screens, keyboard-only and screen-reader use. One contrast check is not an accessibility audit.

  • The product decision

    Why Excalidraw keeps work in the browser and sells cloud storage separately. The business reasons are not visible from the interface.
